# Debian на Acer Iconia Tab 8 (W1-810)

Пошаговая установка Debian 12 (Xfce) на Acer Iconia Tab 8 W1-810 и настройки, после которых планшетом удобно пользоваться без клавиатуры.

[English version](README.md)

## Что работает

| Компонент | Статус | Как |
|---|---|---|
| Загрузка с eMMC | ✅ | 32-битный GRUB и ручная правка `BootOrder` ([шаг 5](#5-починка-no-bootable-device)) |
| Wi-Fi (BCM4330 SDIO) | ✅ | NVRAM от Prowise-PT301 под именем модели |
| Bluetooth (BCM4330B1 UART) | ✅ | Патч `BCM4330B1.hcd` из LibreELEC |
| Звук (RT5640, динамики) | ✅ | `firmware-intel-sound` (квирк для W1-810 уже есть в ядре) |
| Тачскрин (Goodix) | ✅ | Как тачпад Mac: один палец — мышь, два пальца — прокрутка (`scripts/touch-gestures`) |
| Автоповорот (BMA222E) | ✅ | `iio-sensor-proxy` и `scripts/autorotate`, работает и на экранах входа и блокировки |
| Правая кнопка | ✅ | Долгий тап (0,6 с) |
| Кнопка питания | ✅ | Блокировка и гашение экрана, как на телефоне (`scripts/powerbutton-lock`) |
| Сон (s2idle) | ❌ | На ядре 6.1 после пробуждения экран остаётся чёрным; не используется |
| Экранная клавиатура | ✅ | `onboard` с автопоказом в сессии, закреплённая клавиатура на экранах входа и блокировки |
| Камеры (2× Himax HM2056) | ❌ | Нет драйвера сенсора, ISP скрыт прошивкой; выход — USB-вебкамера ([заметки](#заметки)) |

## Особенности железа

- **32-битная UEFI при 64-битном процессоре.** В образе должен быть `EFI/boot/bootia32.efi`. **В Debian 12 netinst он есть, в Debian 13 его нет.**
- **Внутренняя память называется `mmcblk1`**, а не `mmcblk0`.
- **Прошивка не добавляет Debian в порядок загрузки сама**, поэтому после установки появляется «No bootable device». Это исправляет шаг 5.
- **Единственный порт — micro-USB OTG.** Нужен OTG-хаб. Если в нём одновременно флешка, клавиатура и Ethernet, лучше с отдельным питанием.

## 1. Подготовка

- **Образ:** [`debian-12.15.0-amd64-netinst.iso`](https://cdimage.debian.org/cdimage/archive/12.15.0/amd64/iso-cd/debian-12.15.0-amd64-netinst.iso)
  SHA256 `cd4462c06aa8892e692c0c4b9c17802f38c8ab8690e85cbfb5ccaa5956e9af17`
- **Запись через Rufus:** схема **GPT**, цель **UEFI (non-CSM)**, на вопрос про образ выбери **режим DD**. Ventoy не используй: установщик падал на копировании файлов.
- **Понадобятся USB-клавиатура и USB-Ethernet адаптер.** Wi-Fi в установщике не подключился.

## 2. BIOS

1. Включи планшет, удерживая **Громкость +**.
2. **Security:** задай **Supervisor Password**. Без него остальные пункты заблокированы.
3. **Boot:** **Secure Boot** переключи в **Disabled**, а **USB HDD** поставь первым.
4. Нажми **F10**, чтобы сохранить.

## 3. Установка

1. Загрузись с флешки и выбери **Install**.
2. **Сеть:**
   - подключи Ethernet-адаптер до шага обнаружения сети и выбери `eth0` или `enx…`;
   - на вопрос о недостающей прошивке ответь «Нет».
3. **Разметка:** «Авто — использовать весь диск», диск **`mmcblk1`**, все файлы в одном разделе.
4. **Программы:** **Xfce**, **SSH server** и стандартные утилиты. Сними GNOME: он слишком тяжёлый для 1 ГБ ОЗУ.
5. Шаг «Configuring linux-image…» длится 10–30 минут, это нормально.
6. Перезагрузись. На этом этапе ожидаемо будет «No bootable device».

## 4. Режим восстановления

1. Загрузись с флешки и выбери **Advanced options → Rescue mode**.
2. Пропусти настройку сети:
   - «Вернуться» → «Не настраивать сеть сейчас»;
   - или добавь `netcfg/enable=false` в строку ядра (клавиша `e` в меню).
3. **Корневой раздел:** `/dev/mmcblk1p2`.
4. Монтировать `/boot/efi`: **Yes**.
5. Выбери **Execute a shell in /dev/mmcblk1p2**.

## 5. Починка «No bootable device»

```sh
grub-install --target=i386-efi --efi-directory=/boot/efi --force-extra-removable
update-grub
mount -t efivarfs efivarfs /sys/firmware/efi/efivars
efibootmgr -v
```

В выводе найди две записи:
- **`Unknown Device`**: `PciRoot(0x0)/Pci(0x17,0x0)/…/HD(1,GPT,…)`
- **`debian`**: `…\EFI\debian\grubia32.efi`

Записи существуют, но их нет в `BootOrder`. Поставь их первыми, со своими номерами и **без пробелов**:

```sh
efibootmgr -o 0001,0002,2001,2002,2003
```

Затем `exit`, перезагрузка, вытащи флешку. Debian загрузится.

Если записи `Unknown Device` нет, добавь файл через BIOS:
1. Временно включи Secure Boot.
2. В Security выбери **Select an UEFI file as trusted** → `HDD0/EFI/debian/grubia32.efi`.
3. Снова выключи Secure Boot.

## 6. Настройка после установки

Подключи Ethernet, войди в систему и выполни:

```sh
sudo apt install git
git clone https://github.com/disasmic/acer-iconia-w1-810-linux.git
cd acer-iconia-w1-810-linux
sudo ./setup.sh
sudo reboot
# после входа в рабочий стол:
./setup-user.sh
```

**Нет `sudo`?** Если при установке задан пароль root, пользователь не попадает в группу `sudo`. Добавь его так:
```sh
su - -c "/usr/sbin/usermod -aG sudo $USER"
```
Потом войди в систему заново.

`setup.sh` (от root):
- ставит прошивки и утилиты;
- настраивает NVRAM для Wi-Fi и патч Bluetooth с проверкой SHA256;
- включает zram и службу жестов касания (с калибровкой тачскрина);
- ставит хуки LightDM для автоповорота и клавиатуры на экранах входа и блокировки;
- включает onboard в сессии Xfce, а в Firefox — поддержку специальных возможностей, XInput2 и широкие полосы прокрутки.

`setup-user.sh` (в сессии):
- открытие одним тапом на рабочем столе и в Thunar, а для остальных программ двойной клик проще попасть пальцем (30 пикселей и 500 мс);
- отключает сохранение сессии (иначе падение оконного менеджера при выходе «залипает» на следующий вход);
- настройки автопоказа onboard.

Затем подключись к Wi-Fi через значок на панели.

## Заметки

- **Жесты касания** (`scripts/touch-gestures`, служба от root). Служба захватывает тачскрин и подменяет его виртуальной мышью `iconia-touch`. Один палец работает как мышь, но левая кнопка нажимается, только когда понятно, что делает палец: быстрое отпускание — клик, сдвиг больше 15 пикселей — перетаскивание с точки касания (выделение текста, рамка), удержание на месте 0,6 секунды — только правый клик. Поэтому долгий тап никогда не нажимает то, что под пальцем, а выделение нескольких файлов сохраняется. Второй палец переключает на прокрутку, при которой содержимое следует за пальцами:
  - над **Firefox** через второе виртуальное устройство `iconia-touch-mt` передаётся одно настоящее касание, которое идёт за пальцами. Firefox (с `MOZ_USE_XINPUT2=1`) двигает страницу ровно 1:1 и докатывает по инерции. Два одновременных касания он принял бы за начало щипка, а не прокрутки, поэтому передаётся одно;
  - в остальных программах GTK касания для прокрутки не понимает (Thunar начинает перетаскивание, терминал выделяет текст), поэтому используется «натуральное» колесо, пересчитанное примерно в 1:1 для GTK (один щелчок ≈ pow(высота области, 2/3) ≈ 90 пикселей), с инерцией.

  Направление прокрутки учитывает поворот экрана (`autorotate` записывает его в `/run/iconia-rotation`). Калибровка касаний (`CAL` в скрипте) снята с одного экземпляра и убирает сдвиг около 12 пикселей по вертикали.
- **Открытие одним тапом.** Рабочий стол и Thunar работают в режиме одного клика, как на телефонах и планшетах: тап открывает, долгий тап открывает меню.
- **Автопоказ onboard** требует `tablet-mode-detection-enabled=false`. Иначе клавиатура ждёт переключателя «режим планшета», которого у этого устройства нет.
- **Клавиатура на экранах входа и блокировки.** Встроенная клавиатура экрана входа (`onboard --xid`) после поворота становится чёрным прямоугольником. Поэтому хук LightDM `display-setup-script` запускает от root отдельную onboard, закреплённую внизу и всегда поверх, когда появляется окно экрана входа. Хук `session-setup-script` закрывает её при входе. Раз она работает от root, её настройки и выход отключены. Кнопка × прячет её, оставляя маленький плавающий значок. Оконного менеджера на экране входа нет, поэтому клавиатура забирает фокус ввода каждый раз, когда создаёт своё окно (при старте, при повороте). Маленький цикл возвращает фокус окну входа, иначе тап по полю не показывает текстовый курсор. Экран блокировки работает на отдельном графическом сервере (`:1`), поэтому хуки трогают только процессы своего дисплея.
- **Кнопка питания.** Единственный вид сна здесь `s2idle`, и после него дисплей (DSI) остаётся чёрным, поэтому кнопка планшет не усыпляет. Служба `powerbutton-lock` (от root) блокирует сессию и гасит экран, а включает его на экране блокировки только повторное нажатие. Пока экран погашен, служба захватывает тачскрин и кнопки громкости (`EVIOCGRAB`), поэтому они не будят экран и ничего не нажимают. В logind стоит `HandlePowerKey=ignore`, иначе нажатие на экране входа выключает планшет. Графический сервер X не читает устройство кнопки (`axp20x-pek`), иначе само нажатие будит погашенный экран раньше, чем служба успевает решить, что делать, и следующее нажатие включает экран и тут же гасит его снова. У часов RTC нет будильника, поэтому проверить сон через `rtcwake` нельзя.
- **Подсветка.** По умолчанию ядро выбирает `acpi_video0`, а он к панели не подключён: яркость не меняется, и подсветка горит при погашенном экране. `setup.sh` добавляет `acpi_backlight=native` и загружает `pwm-lpss-platform` раньше i915 (через initramfs и `softdep`), иначе i915 пишет `Failed to get the SoC PWM chip`. С `intel_backlight` яркость регулируется, а гашение экрана (DPMS) выключает и подсветку.
- **Автоповорот не задаёт ту же ориентацию повторно**: смена режима через `xrandr` будит погашенный экран, например экран блокировки сразу после нажатия кнопки питания.
- **Камеры не работают и, скорее всего, не заработают.** Обе построены на сенсорах Himax HM2056 (`HIMX2056:00/01`, видны на шине I2C). В ядре Linux драйвера HM2056 нет, есть только старый порт из Android-ядра (см. [kernel bug 195877](https://bugzilla.kernel.org/show_bug.cgi?id=195877)). Процессор изображения Bay Trail (ISP), который нужен драйверу `atomisp`, системе вообще не виден: нет ни PCI-устройства `8086:0f38`, ни устройства в ACPI. Поэтому нет ни одного `/dev/video*`. USB-вебкамера (UVC) через OTG-хаб работает сразу, без настроек.
- **Файлов прошивок в репозитории нет.** Они берутся из пакетов Debian, а патч Bluetooth скачивается из [LibreELEC/brcmfmac_sdio-firmware](https://github.com/LibreELEC/brcmfmac_sdio-firmware).
